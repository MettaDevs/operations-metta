Snapshot 16 November 2026 dari navigasi dokumentasi resmi SATUSEHAT Platform. Tabel ini mencatat operasi yang ditemukan dalam bagian metode HTTP. Satu metode dan path bisa muncul beberapa kali karena sumber mendokumentasikan variasi query atau contoh per domain. Simbol `*` dan `?` mengikuti penanda pada tabel sumber. Tanda — berarti tidak ada parameter atau kelas respons yang terbaca pada bagian tersebut, sehingga kontrak detailnya perlu diperiksa sebelum dipakai.

Gunakan host resmi sesuai environment. Contoh yang membawa `:id` membutuhkan ID server dari environment yang sama. Untuk Patient dan Practitioner, bentuk path detail `/Resource/:id` sudah diobservasi pada uji Sandbox. Katalog juga menuliskan sebagian path Patient dengan tanda titik dua yang menempel pada nama resource. Bentuk di tabel mengikuti path HTTP yang dipakai di contoh API dan bentuk baca detail yang sudah diverifikasi. ## Operasi dari panduan modul di luar katalog FHIR

| Modul | Metode dan path | Kontrak dan batas |
| --- | --- | --- |
| e-Resep v2 | `POST /eresep/v2/sign/in` | Akun e-Resep dalam body JSON, respons token dan timestamp kedaluwarsa. [Login e-Resep](e-resep.md#api-e-resep-v2-untuk-cek-sisa) |
| e-Resep v2 | `GET /eresep/v2/prescriptions/{nrn}` | Token e-Resep dan NRN. Respons memuat resep dan jumlah sisa per item. [Cek sisa](e-resep.md#api-e-resep-v2-untuk-cek-sisa) |
| Resep nasional FHIR | `POST /fhir-r4/v1/DocumentReference`, `GET /fhir-r4/v1/DocumentReference/{id}`, dan `GET /fhir-r4/v1/DocumentReference` | Buat dokumen atau ambil berdasarkan ID/NRN dan `_include=DocumentReference:related`. [Dokumen NRN](../alur/pelayanan-kefarmasian-lintas-fasyankes.md#dokumen-dan-item-resep-berdasarkan-nrn) |
| Resep nasional FHIR | `GET /fhir-r4/v1/MedicationRequest` dan `POST /fhir-r4/v1` | Variasi query `identifier` nasional untuk item. Bundle transaksi pada penebusan. [Resep dan Bundle](../alur/pelayanan-kefarmasian-lintas-fasyankes.md#dokumen-dan-item-resep-berdasarkan-nrn) |
| EpisodeOfCare program | `GET /fhir-r4/v1/EpisodeOfCare` | Variasi koleksi Postman memakai `patient`, `type`, `status` dan Organization yang didokumentasikan pada contoh program. [Kueri EpisodeOfCare per program](kueri-episode-of-care.md) |
| SHK | `GET /fhir-r4/v1/ServiceRequest` | Query nomor rujukan serta daftar order per lab, kategori, asal dan tanggal. [Query SHK](skrining-hipotiroid-kongenital.md#query-publik-dan-korelasi-hasil-shk) |
| Diet dan resep lensa | `POST /fhir-r4/v1/NutritionOrder`, `POST /fhir-r4/v1/VisionPrescription` | Contoh Bearer dan objek FHIR dari koleksi modul. [Gizi](../payload/tumbuh-kembang-dan-gizi.md#antropometri-dan-temuan-gizi) · [Registrasi Mata](../alur/registrasi-mata-dan-telinga.md#registrasi-mata) |
| DICOM Router | `GET /dicom-router-installer` | Unduh ZIP installer Windows dengan Bearer SATUSEHAT. [DICOM](radiologi-dicom.md#endpoint-dan-respons) |
| DICOMweb | `GET /dicomWeb/studies/{studyUID}/series/{seriesUID}/instances/{sopUID}/rendered` | Baca citra rendered. Basis URL dan akses mengikuti instalasi. [DICOM](radiologi-dicom.md#endpoint-dan-respons) |
| Klaim swasta | `GET /webhook-fasyankes` dan `GET /webhook-asuransi` | Unduh paket webhook melalui Bearer sesuai peran. Host publik pada buku modul dicatat di panduan internal. [Webhook klaim swasta](../alur/klaim-swasta-dan-bayar-mandiri.md#webhook-akses-dan-respons-gagal) |
